## 编码器电角度换算与速度补偿说明（2026-10-07，以下10ms测速为修改前）

当前有按速度做角度前推，并非直接使用未经补偿的原始计数。机械计数CPR=4096，极对数p=11。硬件raw在0..4095循环，delta=((raw-previous+2048)&4095)-2048；软件位置position=(position+delta)&4095。启动扫角判断direction为±1，并将末端position记为zero。相对机械计数n=(position-zero)*direction，电角度为theta_e=2*pi*((11*n) mod 4096)/4096。实现用16位整圈：angle=(((n*11)&4095)*16) as u16。每机械计数对应0.087890625机械度、0.966796875电角度；机械一圈正好11电角圈。软件position与raw可能相差初始化常量，该常量通过zero抵消。

运行时使用encoder.speed（电气mHz）预测到输出控制帧的中点。每控制帧100us，N帧读角度和计算、N+1更新写CCR预载、N+2更新实际生效，因此前推时间Delta_t=250us-tick/96（整数微秒，tick为读取编码器时距N帧起点的96MHz计数）。advance约等于speed_mHz*Delta_t_us*65536/1e9；代码用两次32位整数除法实现，最后wrapping_add到angle。以120电气Hz、230us为例，提前角约9.936电角度，而不是机械角度。

补偿覆盖已知软件/CCR流水线延迟，不等同于电机电感电流相位、传感器内部延迟或死区补偿。速度每100个控制帧（约10ms）更新一次，使用窗口真实时间，直接用于前推；日志中的额外低通speed_feedback不用于前推。窗口测速在速度快速变化时有滞后，因此存在改善前推速度估计的空间，但尚未证明这就是抖动根因。实时编码器角度仍每100us读取，不是每10ms才更新角度。

运行Ud=0、Uq>0，逆Park得到alpha=-Uq*sin(output_angle)、beta=Uq*cos(output_angle)，已包含相对d轴的90电角度q轴关系，无需额外手动加90度。无Z情况下zero由每次对齐决定，不等同于MT6701绝对角度零点。本轮核对与记录，未修改或下载固件。

## 三相合成矢量幅值是否随角度不均匀（2026-10-07）

当前算法在理想平均电压层面保持合成矢量等幅，但没有补偿实际功率级的所有非线性。应检查三相去公共分量后的空间矢量模长，而不是三相电压绝对值之和；后者随角度变化本来就不代表转矩变化。

逆Park生成alpha=-Uq*sin(theta)、beta=Uq*cos(theta)（运行时Ud=0），因此理想模长恒为Uq。sampling.rs逆Clarke生成a=alpha、b=-alpha/2+sqrt(3)*beta/2、c=-a-b，代码用23988/32768近似sqrt(3)-1。占空比同时加上DUTY_MIN-min(demand)，该公共分量在线电压差中抵消，不改变理想合成矢量；最小相每60电角发生切换本身不能证明平均幅值跳变。

## 为什么08明显慢于06（2026-10-07）

## 当前控制路径

1. ATIM载波20 kHz（50 μs），RCR=1使更新和CCR预载传送每两个载波发生一次，即10 kHz电压控制。ADC1只在控制帧的第一个载波的两个有效窗口采样；第二个EOS后断开外部触发，下一次真实更新时重新接通。原始样本过流仍即时检查，但第二载波不采样，不宣称连续硬件限流。
2. 第二个EOS后读取GTIM2计数和ATIM时间，将两次母线样本换算成mA，取绝对值最大者作为粗电流指标。该值既不是Iq，也不保证覆盖三相真实峰值。
3. 编码器模4096位置乘11得到电角度。每100控制帧用累计计数与真实时间更新速度，使用等价的32位EAU商余数测速；100 Hz速度PI输出mV。参考速度斜坡50电气Hz/s，速度反馈保留1/4低通。
4. 粗电流采用Q8的1/32低通（约3.2 ms）。未滤波峰值或滤波值超过阈值时，电压上限从当前已用幅度回退10 mV/控制帧；低于阈值减100 mA时，以1 mV/控制帧恢复。运行阈值1100 mA，对齐阈值400 mA。速度积分同步钳制，避免解除限流后的电压突增。输出增加斜坡为2 mV/控制帧，限流下降不受斜坡阻碍。
5. 运行Ud=0、Uq=速度PI请求经限流和斜坡后的幅值；对齐只施加Ud。电压矢量仍按N控制帧计算、N+1真实更新写预载、N+2真实更新生效的管线预测电角度，随后做一次逆Park和PWM调制。

母线电压上限仍为Vbus×10240/32768（12 V时3.75 V），速度PI的Kp=410、Ki=4为电压输出整定起点，需实测。ADC2仍1 kHz采母线与基准。原始样本1800 mA过流、ADC看门狗、母线9.9..16 V、采样超时、编码器跳变/反转/超速、堵转、EAU错误与计算截止保护均保留。粗限流不能代替原始过流保护，也不是精确转矩控制。

载波已提升为20 kHz，仍保留两个各至少10 μs的采样窗口及跨控制帧电压误差补偿。短矢量扩展占载波周期比例增加，脉冲重复两次，可能仍有低频纹波或可听分量；不能仅凭20 kHz设置保证无声。后续需实测对齐、电流、噪声及各档运行。

### 硬件有跳变但计数不变：诊断更新

2026-10-07 用户确认硬件信号有跳变，但尚无 CPU 引脚读值或配置寄存器证据。对照 [RM1.4 第16.8.6节](https://www.whxy.com/uploads/files/20260603/CW32L012_UserManual_CN_V1.4.pdf) 的 x4 编码器示例，CC1E/CC2E 并非所列计数使能条件；第16.3.2.8节的 TI1FP1/TI2FP2 通路也不通过捕获门控。因此未盲目开启捕获通道，未把此项认定为根因。

检查固件新增只读 `ENCODER_REG`：GPIOC 的 DIR/ANALOG/AFRH/IDR，以及 GTIM4 的 CR1/SMCR/CCMR1/CCER/TISEL/PSC/ARR。期望 PC14/PC15 DIR 位为1、ANALOG位为0、AFRH高两半字节均为9；GTIM4 CEN=1、SMS=3、TI1SEL/TI2SEL=0、PSC=0、ARR=65535。诊断使用 unstable-pac 只读访问，不越过驱动写配置。

每次报告前进行约500次毫秒级采样，新增 `observed_edges=[A,B]`、`seen_states`（位0/1/2/3分别表示00/01/10/11曾出现）以及 `movement`（相邻硬件计数差绝对值的累计）。它们避免末尾刚好读到相同电平/计数就误判无变化，但轮询不保证捕捉全部快速边沿，不能作为波形质量或CPR精度证据。

- 实物跳变而 observed_edges 始终为零：优先查 MCU 实际脚位、电平门限、数字输入和复用配置。
- CPU 两相有变化但 movement 始终为零：继续核查 GTIM4 配置、两相正交关系和外设通路。
- movement 非零而 total 接近零：存在来回运动或计数抵消，不能描述成计数器从未工作。

用户反馈比上一版能多跑一档，但噪声很大。读取冻结日志：fault=13、frame=315000、闭环age=49225、speed=73221 mHz（约399 rpm）、filtered=75566 mHz、alignment_travel=77、Iq目标362 mA；start=11015、observed=18687、limit=18600、elapsed=7672、max_control=8095；阶段 last=[695,723,844,3023,2387]、max=[1056,723,858,3927,2387]。计算峰值从9164降至8095 tick（84.32 μs），但较晚第二次采样仍使本轮超时87 tick（0.906 μs）。新增可运行档位不等于全范围时序通过。

噪声原因目前是候选项，尚无麦克风频谱、相电流连续波形或机械振动测量，不能把单点日志当作声学诊断：

- PWM与控制同为5 kHz，PWM载波处于可听频段，电流纹波可能激励电磁声；正弦FOC不保证无声。编译/算术优化没有提高PWM载波频率。
- 单电阻调制强制两个有效矢量窗口各至少10 μs，短矢量会被扩展，误差带到下一帧；零电压请求也不是每帧零线电压，而是交替矢量补偿。因此该调制本身会引入逐帧电流与转矩纹波，低电压请求时需特别关注。
- 电流重建依赖R/L与反电势运输模型，对齐零偏、机械安装及速度PI仍需实测整定。77计数的对齐运动通过现有范围（69..116），但与理想约93有偏差，仅凭该偏差不能定量推断零偏误差，更不能认定噪声由编码器分辨率导致。

本轮还是Timing故障，并非过流故障；362 mA是目标Iq，不是测得的纹波峰值，也不能据此排除电流畸变。frame=315000还是250帧诊断发布点，stage5除调制还包含publish，2387 tick不能全部归于PWM调制本身。后续时序定位应分离这两项开销。

降低噪声需要把载波、最小采样窗口造成的畸变与环路振荡区分开。当前5 kHz尚在最晚采样处触发截止，不能只把PWM/控制常量直接提高到20 kHz；需要先解决计算和单电阻采样安排，再选择载波与电流更新策略。4096计数/机械圈保持已确认值。
