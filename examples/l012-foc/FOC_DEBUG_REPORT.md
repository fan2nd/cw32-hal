# L012 FOC 调试与根因报告

## 结论

闭环“不转、只抖、加电流”的主因不是电源限流，也不是速度环未接入，而是闭环电角度旋转方向与已经验证的开环换向方向相反。错误方向下，q 轴电压启动时会推转子偏移，但随着编码器角度变化，定子电压矢量继续向反方向旋转，最后形成保持力矩并把速度 PI 推到电流上限。

修正 `electrical_angle()`，对编码器相对对齐位置的机械位移取反后，电机已在实机连续换向。RTT 实测反馈达到约 `950–1050 rpm`，目标为 `1000 rpm` 时 `iqref` 大多降到个位到几十，母线保持约 `12 V`，没有再出现电流持续撞墙。

## 调试过程

1. 确认硬件条件：96 MHz 控制时钟、16 kHz PWM、ADC1 在 ATIM CC4 触发 EOS 后进入电流环 ISR，ADC2 连续采样母线和电位器，OPA1/OPA2 前置电流放大器已启用。母线实测约 `12.0 V`，偏置采样约 `ia=2050`、`ib=2057`。
2. 开环先验证相序。开环电角度递减时 SSI 编码器计数也递减，因此相序和编码器方向关系已确定，不再运行方向点动来猜方向。电机为 `11` 对极。
3. 初始闭环日志中，速度环已经输出转矩参考，例如 `target=705`、`iqref=1724..2000`，ADC EOS 计数约每秒 `16000` 次；但 `feedback=0`，编码器只在对齐点附近摆动，随后触发 2 秒无运动保护。这证明速度环和电流 ISR 都在工作，故障在转矩矢量/电角度交接。
4. 检查 SVPWM 时发现手写的扇区排列在 alpha 轴上会把三相结果错误地排列成单相变化。已恢复 C 工程使用的三相中心化计算：`A=v_alpha`、`B=-A/2+sqrt(3)*beta/2`、`C=-A/2-sqrt(3)*beta/2`，再用最大最小值注入公共量。所有中间量保持 32 位。
5. 修正 SVPWM 后，电流环可以跟随，例如 `iqref=215` 时测得 `iq≈219`，CCR 三相也确实改变，但转子仍会偏移后锁住。继续对照开环波形：编码器计数下降时，Park 角若也下降，会使 q 轴电压朝开环相反的 alpha 方向旋转。
6. 将电角度改为：

   ```rust
   let mechanical = u32::from(offset.wrapping_sub(mechanical) & 0x3fff);
   ```

   保持 14 位机械角、`11*4` 转换为 16 位电角度。这个修正后闭环连续换向，速度反馈建立。
7. 最终实测日志包括：

   ```text
   target=1000 feedback=1007 iqref=74  idq=104/18
   target=1000 feedback=838  iqref=297 idq=47/79
   target=1000 feedback=974  iqref=52  idq=-36/14
   target=1000 feedback=992  iqref=21  idq=6/7
   target=1000 feedback=1029 iqref=-28 idq=-4/8
   ```

   母线日志保持在 `12034..12128 mV`，电流没有继续爬升到故障墙。

8. 将上限改到 `6000 rpm` 后，日志出现 `target=6000` 但反馈在几百到一千多 rpm 之间大幅跳变，`iqref` 长时间为 `2000`。复核发现速度公式原来先计算 `delta * 60 * 16000`，在 32 位整数中已经溢出。已改为先使用速度环频率 `16000/16=1000`，计算 `delta * 60 * 1000 / 16384`；6000 rpm 时最大中间值约 `1.57e9`，仍在有符号 32 位范围内。
9. 修正公式后，目标 `6000 rpm` 时反馈先升到约 `2300 rpm`，但 `iqref` 仍为 `2000`，测得 `iq` 约 `0..300` 原始 ADC 计数，三相 CCR 多次接近调制端点，母线仍约 `12 V`。这说明此时是电压/反电动势裕量不足导致速度 PI 饱和；16 kHz ISR 本身没有掉频，不能通过删除几条 ISR 运算解决。继续达到 6000 rpm 需要确认电机反电动势/Kv 后加入有参数依据的弱磁，或降低目标/电流上限以换取稳定性。
10. 在旧版本的 `800 rpm` 配置下人为堵转捕获到 `feedback=0 iqref=2000`，并且母线从约 `12 V` 降到 `9 V`。这暴露出速度 PI 的启动处理不应把零速积分清掉：C 参考在零速仍按 `Kp=100/2^6、Ki=5/2^8` 累加转矩请求，直到转子真正起动。当前 Rust 已恢复这个定点关系；2 秒无运动保护仍会关闭桥臂，避免堵转无限积累。
11. 方向关系没有改变：最新实测日志编码器从 `3601` 降到 `3564`，说明正 q 仍使角度下降。当前速度环不设置应用层 `iqref` 上限，只受 `i16` 传输范围和现有相电流/无运动保护约束；低速抖动应优先观察 `iqref` 是否按 C 的积分路径建立，而不是再次翻转方向。
12. 低速自动启动验证时，未滤波的 16 ms SSI 速度窗口在几个编码器计数之间跳变，速度 PI 将这些量化误差当成正负速度误差，导致 iqref 反复增大并触发母线保护。按 C 的 `ENC_CalcAvrgMecSpeed()` 加入 `(last * 7 + new) / 8` 的 8 点 IIR 后，自动 `120 rpm` 实测反馈约 `73..121 rpm`，`iqref` 降到个位至 `119`，母线保持 `12.06..12.09 V`。临时自动启动已关闭，正式运行仍由电位器给出速度目标。

## 电流环、速度环和软件限流

- 速度环在前台每 `16` 个 PWM 周期执行一次，即约 `1 kHz`，读取 SSI 速度反馈并写入 `CURRENT_IQ_REFERENCE`。
- 电流环在 ADC1 EOS ISR 中执行 Clarke、Park、两个 PI 和 SVPWM，频率约 `16 kHz`。
- 速度 PI 不再设置 `2000` 的应用层 iqref 上限；输出只受有符号 `i16` 传输范围约束。
- 已确认电流采样参数为 `50 mΩ`、`2.5 V` 偏置、`10x` 放大、`5 V/4095` ADC，因此 `1` 个校准 ADC 计数约为 `2.442 mA`。例如 40–80 计数对应约 98–195 mA，200 计数约 488 mA；`CURRENT_TRIP_COUNTS=2000` 约对应 4.88 A 的单相保护阈值。`iqref` 和实测 `id/iq` 现在会同时打印原始计数和 mA。
- 另有每相软件保护：`CURRENT_TRIP_COUNTS=2000`，当校准后的 A/B 相 ADC 差值绝对值超过该值时关闭 MOE。这个阈值同样没有电流传感器的 shunt/OPA 增益标定，不能直接换算成毫安。
- 电流 PI 的电压输出上限为 `27000/32767`，它是电压调制上限，不是毫安限流。
- 因此，当前看到的“堵转约 200 mA”不是某个写死的 200 mA 软件限流值。要把 ADC 数值准确换算成相电流，需要 shunt 阻值、OPA 增益和采样极性；在这些参数确认前，不能把原始计数标成毫安。

## 当前命令映射

电位器低于零区时关闭 MOE、清除速度 PI 和电流 PI；离开零区后才重新使能。有效区采用二次曲线，低端细、高端增长快。当前满量程上限按实测可达速度设为 `240 rpm`。
