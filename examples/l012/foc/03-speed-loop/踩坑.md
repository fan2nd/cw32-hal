# 03 速度环踩坑记录

## 正给定时持续反转

操作者观察到电机反向持续高速运行。以下是修正前同一组 RTT 日志的摘录。转速单位为 rpm，电流单位为 ADC 计数。

| 目标 | 反馈 | Iq 给定 | 实测 Iq |
| ---: | ---: | ---: | ---: |
| 51 | −274 | 23931 | 198 |
| 215 | −276 | 1318 | −54 |
| 240 | −284 | 3537 | 252 |
| 240 | −283 | 7385 | 9 |
| 240 | −288 | 11239 | 365 |
| 240 | −291 | 15067 | 82 |

03 以板级 SSI 计数增加为机械正向。01 记录的 `direction` 表示电角正扫时 SSI 计数变化的符号。在 01 的电压矢量约定下，正 q 轴比 d 轴超前 90° 电角。速度 PI 的给定和反馈均取机械方向，误差为 `target − fb`。发布电流指令时只换算一次，`Iq电气 = direction × Iq机械`。电角预测单独用相同的标定把机械速度换成电角速度。

旧版发布电流时额外取反，反向运动又满足 `abs(fb) >= 5` 的起转判据。在最后四个采样点，目标保持 +240，负反馈读数使速度误差持续为正，积分继续增大。日志中的 23931 是给定值，同一行实测 Iq 为 198。

当时修正后，速度 PI 的积分、输出及叠加起转补偿后的给定均限于 ±200 计数，与 02 的调试范围一致。正转命令下，滤波反馈 ≤ −20 rpm 或 ≥ 860 rpm 立即关桥并锁存故障。当前堵转门槛取目标转速的一半与 5 rpm 中的较小值，持续低于门槛约 2 秒会停机。将电位器归零可清除故障。上表记录的是修正前的故障。随后板端在 +480 rpm 给定下依次测得 +456、+469、+476 rpm，对应 Iq 给定为 −38、−21、−6 计数。当时未验证 800 rpm。现版最高给定为 600 rpm，超速关桥阈值为 660 rpm。

## 480 rpm 时出现 invalid encoder sample

旧版先报 `target=480 fb=284`、`target=480 fb=285`，随后报 `invalid encoder sample` 并关桥。那条旧日志把多种错误合在一起，事后无法判断是哪一种触发。

当前实现分别报告 SSI 传输错误、采样间隔异常和角度跳变。14 位机械角先按一圈回绕求最短有符号差，再按实际采样间隔检查位移。跳变日志带前后角度、差值、允许上限和间隔，可直接复算。后续 +480 rpm 测试的反馈见上表后的板测记录。

## 一开桥就报 1 kHz overrun

当时速度环为 1 kHz。电位器刚过启动点（`pot=220 target=1`）便关桥，归零后可重复。一次日志为 `entry_phase_us=42 exit_phase_us=340 adc_updates=65`。两个时间是 SysTick 周期内的相位，中间可能跨过多个周期，直接相减会漏掉整周期；65 是这段时间内完成的电流环更新次数。

定位靠的是**关桥时的 EOS 计数**。启动日志虽打印 `PWM=16000Hz`，这只是配置目标。板上实测 32,335 µs 内收到 1,014 次 EOS，约 31.36 kHz，偏差在电机通电前就存在。

ATIM 的中心对齐配置有两处被破坏。最初在一次 `CR1.modify` 里依次设置 `CEN=0`、`CMS`、`CEN=1`，硬件只收到最后一次写入。拆成三次写入后，首次设置三相占空比仍会经由 HAL 停表再启动，整写 `CR1` 又把 `CMS` 清零。计数器回到边沿对齐，按上下计数计算的周期缩短了一半。

修正后，修改对齐模式前先实际停表；缓冲型 ATIM 的普通启停仿照 C 版只修改 `CEN`，保留 `CMS`。后续两次启动窗口分别测到 32,284 µs 内 506 次、32,334 µs 内 507 次，均约 15.7 kHz。超时仍会关桥。

## 3 rpm 低速不稳

14 位编码器每机械圈 16,384 个计数。3 rpm 时每毫秒平均只走 0.819 个计数。旧版每帧先换算为整数 rpm，再对整数做 7/8 滤波；从零开始，即使实际匀速，反馈也可能一直为零。速度 PI 还有一次截断：每拍先右移再累加，小的正速度误差无法建立积分。旧的固定 5 rpm 堵转门槛也高于 3 rpm 指令本身。

现在测速保留 1/64 rpm 到滤波之后，速度 PI 先累加再缩放；低于 16 rpm 时平滑减小起动补偿，避免微小给定就打满 Iq。3 rpm 目标对应的堵转门槛为 1.5 rpm。理想 3 rpm 编码器序列回放中，旧算法稳态反馈为 0，新算法为 3 rpm。回放验证了测速量化修正，带载速度波动仍需单独实测。

## 速度环从 1 kHz 调到 4 kHz，再改为 2 kHz

C 参考工程由 BTIM1 每 1 ms 算一次速度 PI。Rust 03 当前由 SysTick 每 **500 µs** 读 SSI、更新速度 PI 和 Iq，ADC1 电流环优先级更高。4 kHz 是中间配置，当时完成了编译，未取得带载板测数据。

改中断频率时，按“每次中断算作 1 ms”累计会同时改变积分增益、加速斜坡和保护时间。当前每拍 PI 按两个 250 µs 单位积分，测速滤波保持约 8 ms，斜坡按实耗时间保持 2 rpm/ms，堵转超时保持约 2 s。复测超时时要看当版的周期，旧日志里的 `1 kHz overrun` 对应旧固件。

## 首次能转，停稳后再次启动堵转

板上先后出现 `target=19 fb=0 iqref=-200 idq=-80/-165`、`target=128 fb=0 iqref=-200 idq=-38/-190`，最后报 `speed fault: target=169 fb=0 previous_iqref=-200`。当次标定为 11 对极、方向 −1、机械零位 6338。负 Iq 与这个方向约定相符。实测 Iq 已接近给定，但计算 Id/Iq 本身就用到了电角度，仅凭这两行无法判断转子角度是否正确。

原版在重新启动时已经把 SSI 机械角换算为电角度并交给 ADC1。查到的时序缺陷是**先开桥、后刷新三相 PWM**，刚开桥时可能沿用上次停机前的比较值。修正后，停机期间也用有效 SSI 帧刷新电角度。重启时先保持关桥，由 ADC1 复位电流 PI 和采样滤波器、按新角度写三相比较值；等一个 ADC 触发周期让预装载生效，再开桥。

运行日志中的 `mech14` 是 SSI 机械角，`elec16` 是按标定换算的电角度，`adc_angle16` 是最近一次电流环实际使用的角度。静止时后两者应接近，比较时要处理 65535 到 0 的回绕；转动时两者采样时刻不同，电流环还会按速度预测角度。

**复测结果：操作者已确认 2 kHz 固件停稳后再次启动正常。** 调试端未捕获这次成功重启的完整 RTT，未量化旧 PWM 对持续堵转的影响。

## probe-rs 报 Unknown，回溯地址不在固件中

一次开桥后出现 `Firmware exited unexpectedly: Unknown`，回溯给出 `0x04770031` 和 `0x0477002e`，均超出这版固件的代码范围。另有重连 SWD 时的 `NoAcknowledge`。这些输出不足以判定发生了 HardFault、复位或速度环超时。

03 的致命异常处理现在先关闭已配置桥的 MOE，再尝试输出 RTT。若进入 HardFault，日志会打印异常栈帧的 PC、LR、xPSR，可与当次烧录的 ELF 核对。该次 Unknown 的根因未确认。

## release 固件偏大

一次测量中 03 占用 35,216 B。包含内联初始化和前台逻辑的 main 约 14.6 kB，独立 RCC 相关符号约 7.4 kB。固定 HSI 启动当时仍带入了其他时钟源的部分校验代码。简化 HSI 专用路径、复用已经算出的时钟后，当版实测 30,476 B，净减 4,740 B。两个数字对应当时的 release 构建；后续增加诊断会改变尺寸。
