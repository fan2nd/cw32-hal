# 01 开环 SVPWM 与编码器标定踩坑记录

修正 SVPWM 幅值换算、改用每 60° 六点标定后，已由板端操作者复测通过。下文的残差数字来自修正前的失败日志。最终复测没有附六点残差或实测电流，因此无法把改善量单独归因于某一项修改。

## 板上实际看到的失败现象

早期标定例程编号为 02，以下旧日志保留当时的编号。第一次运行 02 后切换闭环例程，启动时提示 `missing or invalid calibration; run 02-open-loop`。回看 02 当轮输出，扫场走到了末尾，也估出了 11 对极，但随后又回到等待电位器归零的提示：

```text
electrical residual q16: zero=-3540 +90=-3228 -90=-4756
inconclusive zero: pole_pairs_est=11 hold_counts=334/15262/239
sweep: set pot to zero, then raise it to enable
```

后来带窗口诊断的版本还记录到 `span_counts(start,far,end,+90,-90)=[0, 0, 0, 0, 0]`、`return_delta_counts=-6`，紧接着打印 `02 NOT saved: zero check failed`。当时编码器在每个静置窗口内读数稳定，但各定位点换算出的电角仍有系统性残差，零偏验收失败，程序跳过了本轮 Flash 写入。

## 相序正确，占空比幅值仍可能算错

用相同的 α/β 电压指令，对比原 C 工程的 `FOC_MC_svpwm.c::SVPWM_GetDutyCycles` 和 Rust 输出。取 0° 电角、25% 励磁，统一换算到 3000 个定时器计数：

| 实现 | CCR1 | CCR2 | CCR3 | CCR1 − CCR2 |
| --- | ---: | ---: | ---: | ---: |
| 修正前 Rust | 1781 | 1218 | 1218 | 563 |
| 原 C 与修正后 Rust | 1824 | 1175 | 1175 | 649 |

两组都是 A 相最高、B/C 相相等，仅检查相序会漏掉约 13% 的线电压幅值偏差。比较时应固定输入角、输入幅值和 PWM 周期，再看三相比较值及其差值。

**系数从哪里来。** 第一扇区的两个有效矢量是 `100` 和 `110`，作用时间分别为 Tx、Ty。两相导通时间相减后，零矢量的公共时间抵消，得到 `Da − Db = Tx/Ts`、`Db − Dc = Ty/Ts`。原 C 定义 `Ts = 2 × PWM_PERIOD`，所以比较值差中的 `Tx/2` 除以 `PWM_PERIOD` 后恰好等于 `Tx/Ts`。

在 0° 时，原 C 得到 `Da − Db = (√3/2) × Vα`。旧实现先算 `Va = Vα`、`Vb = −Vα/2`，随后将相电压差除以 2，得到 `0.75 × Vα`。两种标度之比为 `0.75 / (√3/2) ≈ 0.866`。修正后，以 25% 指令逐一对照整圈 65,536 个电角输入，三相比较值相对原 C 的最大偏差为 2 个计数。这里的 25% 是开环电压指令，实际相电流还取决于母线、电机和负载。[SVPWM 实现](../foc-algorithms/src/lib.rs)

## 延长静置要看窗口波动和位置残差

早期版本用折返点及 ±90° 复核零偏。在同一块板上只改变静置时间，记录如下，单位为电角度：

| 静置时间 | 折返点 0° 残差 | +90° 残差 | −90° 残差 |
| --- | ---: | ---: | ---: |
| 0.5 s | −30.08° | −28.85° | −37.00° |
| 1.0 s | −29.84° | −28.85° | −36.76° |

两轮的起点和返回点都是 246、240。两者差 6 个机械计数，按当时估出的 11 对极折算约 1.45° 电角。五个静置点在各自末尾 128 ms 内的读数跨度均为 0。就这次实测而言，延时翻倍对残差影响很小；继续增加同一停稳位置的采样次数也得不到新的角度信息。

当前版本在正扫第一个电周期内依次保持 **0°、60°、120°、180°、240°、300°**。每点取末尾 32 个样本，先处理编码器跨零，再平均。六点共同拟合一个零偏，RTT 按相同顺序打印 `six-point residual q16`。每点残差和窗口抖动的门限均为 2048 个电角计数，即 11.25°。[扫场与验收代码](src/main.rs)

## 方向、极对数和零偏必须配套使用

正反各扫 12 个电周期，用展开后的机械位移估算极对数。正向扫电角时，板级 SSI 读数增加取 `direction = +1`，减少取 `−1`。SSI 驱动已经对帧中的原始角度取过一次反向。机械角每圈 16384 计数，电角每圈 65536 计数，因此从板级机械读数换算到电角要乘 4：

```text
电角 = direction × 实测极对数 × 4 × (SSI机械读数 − 机械零位)  mod 65536
```

历史日志里的 11 对极属于当次辨识。换电机、调整编码器安装位置或改变相线顺序后，应重新运行 01。02–04 从 Flash 读取本次标定使用。[SSI 解码](src/sensor.rs) · [标定换算和记录格式](../foc-algorithms/src/calibration.rs)

## 跑完扫场后，先确认 Flash 写入成功

| RTT 关键字 | 含义及下一步 |
| --- | --- |
| `inconclusive zero` / `01 NOT saved` | 已有极对数估计，但零偏或窗口波动超限，本轮不会覆盖旧记录。查看六点残差和 `span_counts`；电位器归零后再抬高可重试。 |
| `01 FLASH failed during` | 辨识已通过，失败发生在 Flash 操作。按日志中的读、擦、写或校验阶段排查。 |
| `01 FLASH save OK` | 记录已回读核对。此时再切换后续闭环固件。 |

标定页位于 `0xFC00–0xFDFF`，所有 FOC 固件均在链接时避开该页。切换固件时使用按扇区下载；整片擦除会清掉标定。曾遇到 05 报标定无效，回查 02 的最后几行是 `inconclusive zero`，当轮根本没有进入写入流程。[共用链接配置](../firmware-build.rs)
