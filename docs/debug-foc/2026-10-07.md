## 同相原始采样审计

工具 `audit_align.py` 同时支持 Align 与 OpenLoop 的连续 80 帧。它用 duty 排序、各自保持时刻、原始 ADC、记录 VDDA、零点与每帧母线，按实际理想开关边沿积分相电压，直接对同一相相邻原始端点逆解 RL。每轮 157 个区间，不使用固件 first_ma、错时运输、上一 EMF 或 PLL。输出同名 `.audit.json`。这是浮点独立电气模型审计，不是定点观察器的逐位重放。

```powershell
python docs/debug-foc/audit_align.py docs/debug-foc/2026-10-07-align-auto-01.log
python docs/debug-foc/audit_align.py docs/debug-foc/2026-10-07-plateau-auto-01.log
python docs/debug-foc/audit_align.py docs/debug-foc/2026-10-07-plateau-second5-01.log --second-blank 480
python docs/debug-foc/audit_align.py docs/debug-foc/2026-10-07-plateau-restored-01.log
```

- Align 三相残差 RMS 为 56.56／51.52／56.52 mV，最大绝对值约 149 mV。Align 控制状态不独立证明转子静止，不能将其等同真实反电势测量。
- OpenLoop 5／2.5 µs 相邻一帧区间跳变 RMS／峰值为 133.55／524.36 mV；第二通道同相 B 的约 431→955 mV 跳变在 n49→50，使用同相原始端点即可复现。
- 5／5 µs 为 137.96／605.78 mV，恢复复测为 131.45／542.23 mV。更晚第二采样未显示改善，故恢复原延时；不是证明全部模拟建立问题已排除。不同试验的机械轨迹和采样时刻不同，不能作严格配对电流比较。
- 旋转时 RMS 本身含真实旋转 EMF，不能将 600–700 mV 的 EMF RMS 当作噪声 RMS；比较的是邻接区间的变化量，也仍包含真实 EMF 变化。

固定 R=3.35 Ω 的 L 敏感性扫描（350、500、650、750、875、1000、1250、1500 µH）显示：Align 的相邻跳变 RMS 在 875 µH 附近最低约 71 mV；350 µH 为 401 mV。旋转 5／2.5 µs 在这组候选中 350 µH 为 83 mV、875 µH 为 134 mV；5／5 µs 分别 84／138 mV。扫描仅改变离线模型，固件仍为 875 µH。不能仅凭“变化更小”识别真实动态电感：降低 L 也会压低电流差分放大项，且电感可随转子位置、频率和电流变化。两个阶段不支持直接用单个较低 L 取代原值。

## 结论及未完成项

已实现无需按键的单次实板启动、取得并保存四轮完整诊断、恢复无改善的采样改动，并将当前缓冲移回旋转平台 v4 以便后续定位。没有放宽接管门槛、增加电流、延长超时或调整 PLL/R/L。

无感接管尚未修复。现有证据将重点缩小到旋转阶段的电气观测输入／模型，而不能只归因 PLL 参数或第二样本 2.5 µs 延时。进一步识别需要独立实测 PB0 与分流器电流在开关边沿附近的波形、实际门极／相电压，并测量不同转子位置及测试频率下的线间电感；当前 ST-Link/RTT 无法获取这些模拟量。仍未完成门极、实际瞬时相电流和独立转子角度验证。

ARM release 与 07 修改文件 rustfmt 检查通过；原有 proc-macro-error2 未来兼容性提示仍存在。新增审计保留原始日志，拒绝缺行、乱序 age 和不完整 trailer。结果和工具位于本目录，未提交 Git。

## 启动流程与“有反电势即可接管”的区别

用户问：电机已经转起来、有反电势，为什么还不进入下一步？

当前实现从上电开始先校准约 256 ms，台架线程在上电 3 s 发出启动请求。启动后执行约 5 ms 低侧自举、200 ms 固定角 150 mA 对齐，然后在强制旋转坐标系中闭环调节电流，指令 250 mA，电气频率从 2 Hz 在 2.5 s 内升到 18 Hz。OpenLoop 指角度／速度开环，不是电流环也开环；观察器从进入 OpenLoop 即每帧更新，已在利用反电势。

代码只在 2.5 s 加速结束后才累计接管资格。需要估计反电势至少 500 mV、已跟踪、正向速度至少 8 Hz 且低于 80 Hz、与强制速度相差不超过 max(强制速度/4, 2 Hz)，以及角差／PLL 质量门同时通过。平台 18 Hz 对应速度差门为 4.5 Hz。

角差观察器减强制角需在 -60°..+10°；同一候选窗口峰峰值不超过 20°。PLL 残差峰值不超过 20°、累计 RMS 不超过 10°、连续超10°不足4帧且窗口总数不超过50帧。所有条件需连续1000帧（250 ms），任一拒绝清零，实际切换帧还要求角差不为正。开环状态累计5 s仍不通过则StartupTimeout。

通过后进入0.5 s Blend：接管帧保持原αβ电压，把电流指令和PI状态转换到观察器坐标系，后续使用观察器角度控制，逐渐消退Id。Blend不是0.5 s角度线性插值。随后ClosedLoop速度参考向25电气Hz爬升。

有足够可用反电势后即可开始接管，这是正确的总体方向；FOC还需要从其矢量方向得到可信的连续转子角度，而不能只看幅值非零。本例反电势是用PWM电压模型和电流逆解得到，不是独立相电压直接测量，模型／采样误差也会形成估计矢量。I/f电流轴与转子轴之间还存在正常负载角，不应要求两角严格相同。[Imperix I-f 启动说明](https://imperix.com/doc/implementation/i-f-startup-method)解释了低速反电势限制及电流坐标系切换时的过渡问题。

最新复测结束时估计反电势802 mV，已超过500 mV门槛；平台10000帧中低幅值拒绝71帧、角差拒绝205帧、PLL拒绝29帧，可能同帧重叠。最长连续资格77帧约19.25 ms，所以当前卡在资格连续性，不是没有动起来或没有反电势。末次失败窗口角差范围约20.83°，刚超过代码的20°上限；这仍不能证明真实转子角误差大小。

固定2.5 s加速、只在平台评估、250 ms连续资格、20°变化界等都是本例的工程选择，不是无感FOC的理论必要条件；其组合尚未得到成功实板接管验证。不能把代码拒绝等同于物理上一定无法接管，也不能由已有反电势就断定切换一定稳定。后续可以重审速度相关的角度可信度与过渡策略，允许可观测后尽早接管；本次问答仅解释现状，没有修改固件或重新启动电机。
