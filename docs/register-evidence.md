## CPU and executable memory

The official CMSIS header defines Cortex-M0+ r0p1, two NVIC priority bits, VTOR
present, no MPU, and the standard vendor-independent SysTick. The matching
Rust target is `thumbv6m-none-eabi`. The device's 32 external IRQ numbers are
recorded in the family YAML directly from `IRQn_Type`.

RM V1.4 table 2-1 and the SDK's Template MDK project agree on:

| Region | Start | Length | Inclusive end |
| --- | --- | --- | --- |
| Main Flash | `0x00000000` | 64 KiB | `0x0000FFFF` |
| SRAM | `0x20000000` | 8 KiB | `0x20001FFF` |

The Flash **controller** at `0x40022000` is not executable Flash memory. Do not
substitute the common STM32 Flash base `0x08000000`.

## SYSCTRL and reset-clock policy

SYSCTRL base is `0x40004000`. CR0/CR1/CR2 and AHB/APB clock-enable registers
require `0x5A5A` in bits 31:16 on every write. GPIO clocks are initially off.
AHBEN is at `+0x30`; GPIOA/B/C/F use bits 4/5/6/7. GPIO peripheral reset is
AHBRST at `+0x40`, with the same bits but **active-low** polarity. The vendor
reset macros clear a bit to assert reset and set it to release reset. AHBRST
does not have the clock-enable register's key field.

At reset, CR0=`0` selects HSI and undivided AHB/APB; CR1=`1` enables HSI. HSI
is at `+0x18`; DIV is bits 14:11. Encoding 14 means oscillator /24, yielding
nominal 4 MHz from the nominal 96 MHz oscillator. STABLE is bit 15; TRIM is
bits 10:0. CR0 HCLKPRS is bits 7:5 and PCLKPRS bits 4:3.

`rcc::init_reset_clock()` deliberately supports only this reset configuration.
It first reads and validates the source, dividers and HSI enable; then it loads
16-bit factory codes at `0x001007C0` (HSI) and `0x001007C2` (LSI), masking to
11 and 9 bits respectively. The official startup's blank-code fallbacks are
`0x77A` and `0x59`. It preserves other fields, waits a bounded number of polls
for HSI stability, and verifies configuration and trim readback before returning
nominal 4 MHz frequencies. It never claims that the silicon frequency was
measured, nor does it switch to 96 MHz or alter Flash wait states.

## GPIO layout and semantics

| Port | Base | Implemented logical pin mask | AHBEN bit | IRQ |
| --- | --- | --- | --- | --- |
| A | `0x48000000` | `0xFFFF` | 4 | 5 |
| B | `0x48000100` | `0xFFFF` | 5 | 6 |
| C | `0x48000200` | `0xE000` (13,14,15) | 6 | 7 |
| F | `0x48000300` | `0x00CB` (0,1,3,6,7) | 7 | 8 |

These are implemented logical pins, evidenced by the DIR reset masks and SDK
pin-function macros. Exact package pin numbers must be checked against the
chosen C8T6/C8U6 package; no unverified package mapping is invented here.

| Register | Offset | Relevant behavior |
| --- | --- | --- |
| DIR | `0x00` | 0 output, 1 input |
| OPENDRAIN | `0x04` | 0 push-pull, 1 open-drain |
| PDR | `0x0C` | Only PF03 implements an internal pull-down |
| PUR | `0x10` | Per-pin pull-up enable |
| AFRH | `0x14` | Pins 8–15, 4 bits each |
| AFRL | `0x18` | Pins 0–7, 4 bits each; GPIO AF encoding is zero |
| ANALOG | `0x1C` | 0 digital, 1 analog |
| RISEIE / FALLIE | `0x24` / `0x28` | Per-pin edge interrupt enables |
| ISR / ICR | `0x34` / `0x38` | ICR is **write-zero-to-clear**, not W1C |
| FILTER | `0x40` | GPIO interrupt filter configuration |
| IDR / ODR | `0x50` / `0x54` | Input / output-latch data |
| BRR | `0x58` | Write low-halfword bits to reset output latches |
| BSRR | `0x5C` | Low halfword sets; upper halfword resets |
| TOG | `0x60` | Write bits to toggle output latches |

For push-pull GPIO output: enable its keyed AHB clock, select AF zero, clear
ANALOG, configure pull resistors and OPENDRAIN, preload the desired latch with
BRR/BSRR, then clear DIR. Serialize read-modify-write operations. This ordering
lets the HAL preload a latch before actively driving it.

PA13/PA14 default to SWD. They are unavailable as GPIO while CR2.SWDIO is zero.
Setting that bit disables SWD, so a safe bring-up HAL must not do it silently.
PF03 is also BOOT; account for the board's boot straps before driving it.

## Known source inconsistencies and limits

- RM V1.4 prints HSI reset value `0x0001F772`, while calling bits 31:16 reserved
  and naming a different default TRIM value in prose. The implementation relies
  on verified divider semantics and factory trim, not that whole-register value.
- RM table 2-1 labels BootLoader space `0x00100000–0x001009FF` as 2 KiB, although
  the printed range is larger. It is excluded from executable linker memory.
- Different IDE copies of the vendor SVD can lag one another. The current
  `Libraries/inc/cw32l012.h` plus RM V1.4 are the implemented register authority;
  no claim of an exhaustive, generated or independently validated PAC is made.
- Unit tests can check offsets, masking and rejection of wrong clock settings.
  They cannot establish physical pin operation, timing accuracy, flashing
  support, electrical safety or correct behavior on actual silicon.
