# Current Embassy API alignment and remaining work

The current work fixes the PAC/indexed-register architecture, GPIO shared-driver/interrupt design, ADC/comparator owner/mode/channel design, and generic owned timer/PWM channels. It does not claim that every CW32 HAL API now matches embassy-stm32. Earlier explanations presenting missing Flex/open-drain as “avoiding fictitious hardware” were incorrect: Flex is a software ownership/implementation structure, and both CW32 chips have OPENDRAIN hardware.

The HAL comparison is pinned to Embassy commit [`b12a6d9efcd2711037abca1b63a661a9ef726444`](https://github.com/embassy-rs/embassy/tree/b12a6d9efcd2711037abca1b63a661a9ef726444). PAC comparison uses chiptool [`bcf538a2e7b8584ae874ee9ab72efb1576fc6152`](https://github.com/embassy-rs/chiptool/tree/bcf538a2e7b8584ae874ee9ab72efb1576fc6152) and the corresponding typed stm32-metapac structure. Exact usage and coverage are in [PAC/GPIO](pac-gpio-v0.13.md), [schema5](schema-v5.md), and [all46 IP decisions](register-array-coverage.md).

| Peri/singletons | Uses official embassy-hal-internal0.5.0 Peri, PeripheralType, peripheral macros, lifetime/reborrow/erasure | Metadata filters GPIO/SYSCTRL/shared channel ownership according to CW32; no fabricated DMA channel tokens |

| GPIO capabilities | Real indexed CW32 access, safe-owner pin erasure, Drop disconnect, preload-before-output; both-chip open-drain | L012 has fixed hardware speed and PF03-only pull-down. F030 exposes genuine speed and independent drive strength. These hardware differences remain explicit |
| RCC/clock trust | Checked initialization and bounded stabilization; clock fields are crate-private, getters expose validated initialization snapshots | Narrow fixed configurations; no supported safe runtime reconfiguration. Clock-tree coverage and some public constructor details still differ from upstream |
| ADC | Actual Adc<I,M> owner, blocking/Binding constructors, sealed per-call channel borrows, borrowed fixed-N Sequence extension, cancellation and internal RCC frequency | CW settling/poll limits and sequence capabilities differ; F030 watchdog is single-channel MODE0 only. No calibration/DMA/internal-source owner API |
| Comparator | Actual Comp<I,M> owner, disabled construction, explicit enable, startup/readiness checks, checked IRQ subscriptions/cancellation and reference-resource borrows | L012 shared reference/DAC topology and F030 READY/brake safety are intentional hardware-specific constraints |
| Timer/PWM | Real low_level::Timer plus SimplePwm/PwmPin, independently optional channels, exclusive borrowed SetDutyCycle handles, metadata-generated ATIM/GTIM routes, validated frequencies | Edge-aligned upcounting and main outputs only; no generic capture/encoder/DMA/complementary API. CW prescalers, channel count and update behavior remain explicit |
| Specialized ATIM | ThreePhasePwm retains complementary pins/break ownership, initially disabled power outputs and explicit fault recovery | Its strict three-phase atomic-update contract is separate from independent SimplePwm channels; no claim of uninterrupted FOC control |
| CORDIC/EAU | Owned accelerators and CW-specific operations, typed MMIO; CORDIC has real IRQ future/cancellation | Do not add mode parameters solely for visual similarity; APIs follow the actual accelerators |

## GPIO behavior that is deliberately preserved

Safe drivers own Peri tokens; identity values are not exclusive ownership. `Peri::into()` erases pin identity as in the pinned upstream version; no invented degrade facade is added. L012 unsupported Pull::Down requests fail before MMIO. Explicit release returns the token without touching the current mode/latch; ordinary Drop disconnects only the owned pin to floating digital input and preserves the shared clock/latch. Direct PAC use still requires application-level clock and hardware-ownership discipline.

## Remaining scope

The identified PAC/array, GPIO, ADC/comparator ownership and generic timer/PWM architecture changes are implemented and reviewed. This does not establish complete embassy-stm32 feature parity. General UART/SPI/I2C/DMA HAL drivers, timer capture/encoder/DMA and a generic complementary-PWM API, ADC calibration/internal-source ownership, and unsupported low-power/clock modes remain outside the implemented scope. The existing ThreePhasePwm retains the actual CW motor-specific constraints. See [timer API and hardware differences](timer-pwm.md).

These are API/ownership tasks, not claims justified by compiling names. Source review and external probes accompany actual builds; no chip has been flashed and no timing/electrical behavior was measured. See [async ownership/contracts](async-api.md), [HAL cfg layering](hal-cfg-layering.md), [v0.13.2 structural validation](validation-v0.13.2.md), [v0.13.1 layering validation](validation-v0.13.1.md), and the prior [v0.13.0 API verification](validation-v0.13.0.md).

The new whole-chain findings and corrections are recorded in [v0.14.0 audit](full-chain-audit-v0.14.0.md); that record supersedes older packaging/time-contract claims.
